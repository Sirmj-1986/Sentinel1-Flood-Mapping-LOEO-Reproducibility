# Multi-Event Sentinel-1 Flood Mapping Reproducibility Repository

This repository contains the reproducibility workflow for the manuscript:

**Multi-Event Sentinel-1 Flood Mapping Using Adaptive Otsu Thresholding and Machine Learning in the Lokoja–Bassa–Kogi Sector of the Niger–Benue Confluence**

The public code is intentionally limited to the analytical pathway reported in the manuscript. Superseded experiments, deep-learning development, temporary runtime-recovery cells, author-specific Google Drive paths, and exploratory cartographic code are excluded.

The manuscript study-area map was prepared separately in **ArcGIS Pro** and is not generated by this repository.

## Repository scope

The notebook reproduces the reported analytical workflow:

1. Environment and configuration
2. Sentinel-1 preprocessing and acquisition matching
3. Predictor construction and grid harmonisation
4. Reference-sample preparation
5. Leave-One-Event-Out (LOEO) partitioning and spatial blocking
6. Event-specific adaptive Otsu benchmark
7. Random Forest, XGBoost, and LightGBM development comparison
8. Independent held-out evaluation and full-area LightGBM inference
9. Paired Otsu-LightGBM statistical comparison
10. Full-area flood mapping and spatial agreement
11. Held-out TreeSHAP interpretation
12. Post-selection sensitivity analyses
13. External NEMA flooded-location corroboration
14. Reproducibility audit and manuscript outputs


## Main code

`reproduce_flood_mapping_study.ipynb`

This is the single public analytical notebook. It uses repository-relative paths and does not require access to the authors' Google Drive.

## Reproducibility levels

### Level A: Core numerical reproduction

The smallest reproducibility package can contain:

- `data/processed/loeo_12predictor_table.csv`
- `data/processed/otsu_heldout_predictions.csv`

With these files, the notebook can reproduce the central machine-learning evaluation, paired Otsu-LightGBM comparison, bootstrap confidence intervals, McNemar tests, held-out TreeSHAP summaries, threshold sensitivity, predictor-group ablation, seed/hyperparameter robustness, and prevalence-adjusted performance.

### Level B: Full map reproduction

To regenerate event maps and spatial agreement statistics, also provide:

- `data/processed/rasters/predictor_stack_2018_12band_10m.tif`
- `data/processed/rasters/predictor_stack_2022_12band_10m.tif`
- `data/processed/rasters/predictor_stack_2024_12band_10m.tif`
- `data/processed/rasters/jrc_permanent_water_10m.tif`

### Level C: Source reconstruction

For source-image reconstruction from Google Earth Engine, provide:

- `data/inputs/roi.geojson`
- Earth Engine credentials for the user running the notebook
- an optional Earth Engine project ID supplied through the environment variable `EE_PROJECT`

No author-specific Earth Engine project is hard-coded.

## Quick start

### Local Python/Jupyter

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
jupyter lab
```

Open `reproduce_flood_mapping_study.ipynb` and run the cells in order.

### Google Colab

The notebook can be opened from a public GitHub repository or uploaded directly to Colab. **Google Drive does not need to be mounted.** The default path is the repository working directory.

If the processed reproducibility data are archived separately as a ZIP file, define a direct archive URL before running the configuration cell:

```python
import os
os.environ["FLOOD_REPRO_ARCHIVE_URL"] = "DIRECT_URL_TO_REPRODUCIBILITY_ARCHIVE.zip"
```

Alternatively, point the notebook to a local data directory:

```python
import os
os.environ["FLOOD_DATA_ROOT"] = "/path/to/reproducibility_data"
```

## Public-data reconstruction

The workflow uses public or publicly documented Earth-observation products for the geospatial predictors:

- Copernicus Sentinel-1 GRD
- ALOS AW3D30 elevation
- MERIT Hydro
- JRC Global Surface Water

Users who reconstruct source imagery do so through their own data-service credentials and are responsible for complying with the source datasets' terms of use.

## Final predictor order

The public workflow uses exactly 12 predictors, in this order:

1. `VV_pre`
2. `VH_pre`
3. `VV_event`
4. `VH_event`
5. `dVV`
6. `dVH`
7. `PolContrast_pre`
8. `PolContrast_event`
9. `Elevation`
10. `Slope`
11. `HAND`
12. `Log_UPA`

Distance to drainage is not part of the reported model.

## Locked analytical settings

The notebook retains the final manuscript settings, including:

- Events: 2018, 2022, and 2024
- Analysis CRS: `EPSG:32632`
- Analysis pixel size: 10 m
- LightGBM decision threshold: 0.53
- Otsu input: full valid `VV_event` histogram
- Otsu histogram range: -40 to +10 dB
- Otsu bin width: 0.025 dB
- Expected Otsu thresholds: -14.8125 dB (2018), -13.8375 dB (2022), -15.2375 dB (2024)
- Spatial development blocks: 10 km x 10 km
- Train-validation non-overlap guard: 2.56 km
- Paired bootstrap replicates: 5,000
- Bootstrap seed: 20260811
- Frozen LightGBM threshold: 0.53

## Post-selection sensitivity analyses

The notebook keeps robustness analyses separate from the primary model-selection pathway. The sensitivity section includes:

- 5 replicate seeds
- 13 candidate configurations per model family
- 3 model families
- 195 model-seed-configuration evaluations in total
- fold-specific threshold sensitivity
- five predictor-group ablations at the frozen 0.53 threshold
- prevalence-adjusted PPV/NPV calculations

These analyses are diagnostic and do not retrospectively redefine the primary classifier.

## External NEMA validation

The NEMA flooded-location file is optional and is expected at:

`data/restricted/nema_flood_locations.csv`

The required columns are:

- `Longitude`
- `Latitude`

If the file is absent, the notebook skips the external validation cleanly. This permits public release of the code even where redistribution of agency-supplied coordinates is restricted.

The external analysis is a flooded-location corroboration only; it is not treated as a complete accuracy assessment because the external dataset contains no non-flood class.

## Three-class raster encoding

Final Otsu and LightGBM maps use:

- `0` = non-flooded land
- `1` = permanent water
- `2` = event flood
- `255` = NoData

Permanent water is defined independently using JRC Global Surface Water seasonality = 12.

## Data release policy

Large raster products are intentionally not embedded in the Git repository. They should be deposited in an accompanying archival repository such as Zenodo, Figshare, or OSF and linked by a persistent DOI or direct archive URL.

Reference coordinates and agency-supplied NEMA coordinates should only be redistributed where the authors have permission to do so. Where redistribution is restricted, the repository should provide the code and documented file schema without exposing the restricted coordinates.
